# Riservatezza (rete, memoria, pulizia, avvertenze)
Stato attuale. ≤ 25 KB, righe ≤ 600 caratteri. Regole di fondo: niente esce dal browser, nessuna telemetria, nessun dato sulla persona, un campo sconosciuto si toglie.

## Rete e memoria del browser
- CSP di `web/index.html` esatta (costante `EXPECTED_CSP` in `tests_e2e/riservatezza_statico.mjs`): `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; connect-src 'self'; img-src 'self' data: blob:; style-src 'self'; font-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'`. Cambiarla = cambiare anche la costante, con una decisione del proprietario. Nessuna risorsa di terzi (CDN, font, mappe, analytics, video).
- T1 (statico, senza browser): la CSP è uguale all'attesa; in `web/` nessun URL `http(s)://` fuori da `tests_e2e/link_ammessi.json` (file + URL + motivo; una voce che non compare più nel file fa fallire), nessun `@import`/`src="//`, nessun `sendBeacon`/`WebSocket`/`EventSource`/`XMLHttpRequest`. Un link nuovo (solo testuale) va aggiunto a `link_ammessi.json`.
- T2 «canarino» (`tests_e2e/riservatezza.mjs`, generatore in `canarino.mjs`): un JCAMP sintetico con metadati canarino (nome campione, `C:\Users\CANARIO\`, operatore, seriale, data e ora) viene dato al selettore file e la pagina fa tutto ciò che sa fare.
- Controlli di T2: (a) zero richieste verso altre origini e zero violazioni CSP, (b) nessun canarino in localStorage, sessionStorage, IndexedDB, OPFS, Cache Storage, cookie, DOM, file scaricati, (c) dopo il ricaricamento nessun dato del campione e solo le preferenze `checkir.lang|theme|panel`. Prove di controllo nello stesso file: una `fetch` verso un'altra origine e un canarino scritto in localStorage/OPFS DEVONO essere rilevati.
- **Regola: ogni nuova azione o esportazione della pagina si aggiunge a T2** (`doEverything` in `riservatezza.mjs`: un click o una chiamata in più; i file scaricati sono già letti e cercati).
- Eccezione al canarino per la cartella osservata: se la persona spunta «Ricorda la cartella», IndexedDB `checkir-folder` contiene la sola chiave `watched` col riferimento alla cartella (mai nomi di file né dati); spuntando di nuovo si cancella l'intero database. `doEverything` la usa con una cartella finta (`FAKE_PICKER` in `cartella.mjs`) e la lascia spenta.
- Librerie private (`libraryImportScenario` in `riservatezza.mjs`): l'importazione non fa richieste dalla pagina e in OPFS entrano solo lo spettro e il nome del file; i metadati del JCAMP-DX (campione, operatore, percorsi, seriali) non compaiono in nessun archivio. Il nome del file scelto dall'utente come nome del composto è l'unico testo che resta, di proposito.
- `tests_e2e/sito.mjs`: server statico di `site/` per i test. CI: job `web`, dopo `fumo.mjs`.

## Contratto di pulizia (`anonimizza/1`)
- Per ogni lettore del registro `READERS`, ogni campo dei metadati ha un'azione: `tieni` (parametri fisici e di formato), `generalizza` (data → `AAAA-MM`) o `togli` (nome, descrizione, percorsi, utente/operatore, seriali, commenti, testo libero); un campo non elencato si toglie. Codice: `crates/ftir-core/src/anonimizza.rs` (tabelle `CONTRACT`, `clean`, `Report`); dettagli in `motore.md`. Schema: `docs/schemi/anonimizza-1.json`.
- Non distruttiva: `clean` lavora su una copia dei metadati, l'originale non si tocca; il rapporto di pulizia (ambito, chiave, azione, conteggio) non contiene mai un valore e mostra `(unknown field)` per le chiavi che il contratto non conosce. `readers/anonymize.rs` (pseudonimi stabili HMAC) resta lo strumento per confrontare file dentro lo stesso servizio; l'esportazione che esce dal browser usa il contratto.
- Un lettore nuovo = una tabella in `CONTRACT` + una riga in `declared()` di `crates/ftir-core/tests/anonimizza.rs` (T4); un campo nuovo di un lettore = una regola nella sua tabella, altrimenti il test fallisce. Dopo ogni modifica: `cargo run --release -p ftir-core --example gen_anonimizza`.
- T3 (`tools/controlla_schemi.py`): vedi `dati.md`; un campo `email` in uno schema fa fallire il job `data`.
